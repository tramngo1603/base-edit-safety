Base Edit Safety

Install, run and read a local guide-sequence search.

1. Install and start

The steps below install a complete offline handoff. A source ZIP or wheel requires Python and the native backend separately; follow the project README for that installation.

The supported, tested environment is macOS Sonoma 14.4.1, Apple silicon (arm64), Apple M3 Pro GPU, 18 GiB RAM. Other Macs and operating systems have not been tested. Full-reference work requires at least 16 GiB RAM, 4 GiB available RAM and 25 GiB free disk space. Keep one large genomic job running at a time.

  1. Extract the entire handoff ZIP into a writable folder on this Mac. Keep its files together.
  2. Double-click Start.command. Setup uses the included Python and dependency wheels, checks file hashes, and tests the real Cas-OFFinder/OpenCL backend. Installation is offline and needs 2 GiB free.
  3. The Base Edit Safety window opens. Keep its terminal window open while using the app.

No existing Python, Homebrew, Docker, account or cloud service is needed. If macOS blocks opening the unsigned launcher, use Finder’s Open action or the normal Privacy & Security “Open Anyway” flow after verifying the handoff’s source. Do not disable system security settings.

2. Try an example

Open Try an example and pick one of three bundled runs:

  • Reference only — mock DNA, a few seconds, no sample. Use it to inspect candidates and exports.
  • Reference + sample — mock DNA with a small variant file; checks the local backend end to end. It must finish with one retained locus, one gained locus, one changed sequence at the retained locus, and three sequence configurations.
  • Public HG003 — 23 published guides across all 24 primary GRCh38 chromosomes. Choose a cache folder and an output folder, then continue to Review & run and press Start analysis. Missing public inputs are downloaded and prepared automatically; downloaded files are checksum-verified before reuse. Download: 1,130,871,852 bytes (1.13 GB); reserve 25 GiB on both selected filesystems.

To prepare the public reference without starting an analysis, use My analysis → Prepare reference… → Prepare & use reference. Preparation runs once; later analyses reuse the verified cache.

The HG003 sample reconstruction processes all 22 autosomes, with local exclusions for unresolved sequence and phase. X/Y calls and sample ploidy are not supplied. Preparation retains all 4,000,097 VCF rows. Allow 10–30 minutes for a search, plus download and preparation time. Setup checks available resources first.

The reference search has 706,588 loci. Donor coverage, locus changes and sequence changes are checked against the versioned expected-results file. Processing a chromosome does not mean every region was resolved. Timestamps and resource measurements are checked separately. The expected-results file is expected-hg003.json.

3. Use your own guides and VCF

  1. Open My analysis. Paste one 20-base spacer per line, without PAM, or use Open guide file… to select a text file. A TSV may instead contain exactly guide_id and spacer_sequence columns. Use 1–32 unique guides.
  2. Select a full, uncompressed GRCh38 FASTA with chr1–22/X/Y names under Reference genome. If public preparation is complete, Use prepared public reference fills this in. An adjacent FASTA index is created when needed.
  3. Add sample variants — optional: select a VCF and choose its sample. The VCF must declare ##reference=GRCh38 and use matching chromosome names. Confirm two copies of each autosome only if that describes the sample. X/Y are left unresolved. For other ploidy, use the advanced workflow with an analyst.
  4. Additional details — optional: editor, cell-source and variant-source labels are saved with your export; they do not change the search.
  5. Choose an output folder, continue to Review & run, check the summary, then press Start analysis. The request is created automatically. VCF normalization and REF checks happen locally, preserving ALT indexes and supplied phase.

The search uses NGG, both strands, up to six mismatches and no gaps. The default sample policy uses explicit PS phase sets, accepts PASS and “.” filters, and applies no GQ/DP cutoff. Missing calls remain unresolved. Input requirements are also shown beside each control. Original genomic files stay local and are not uploaded.

4. Read the results

When a run finishes, the results screen opens. Use Overview, Candidates and Sample differences to inspect each guide. Search & filters narrows the candidate table; the table shows up to 5,000 rows at a time. Under Learn more: Coverage and Run details summarize scope and settings, Full report opens results/report.html in a browser without a server or internet connection, and Open folder shows the complete result files. Every run has a new dated folder; Open results… in the app header reopens a completed analysis without a rerun.

Export… creates a separate dated export folder and never changes the saved analysis. Candidate tables can be exported as all candidates, all rows matching the current search and filters, or the selected rows; all and matching exports read the complete files beyond the table display limit. Each export records its selection criteria, the available scientific fields, the source files and hashes, and a short field dictionary. The HTML report and a full analysis copy can be exported the same way.

Open TSVs in Excel, Numbers or LibreOffice as tab-separated text; keep IDs as text. Coordinates start at zero and exclude the end. A “sample incomplete” message means only the reference completed. Unresolved sites do not count as losses. Optional experimental evidence is not included in these examples.

5. Fix common setup problems

MessageNext step
OpenCL/backend check failedRead the named setup-check log. Use the tested Apple silicon Mac environment. Restart after OS/driver repairs. A Python wheel or Docker installation does not supply a working OpenCL runtime.
Not enough memory or diskClose other large applications or choose a filesystem with 25 GiB free. Keep existing evidence and choose a new output folder.
Download interrupted / checksum mismatchRetain the failed cache for inspection. Choose a new cache folder; verified complete raw files may be copied into its matching data/ subfolders. Partial .part files are never treated as complete.
VCF/reference mismatchCheck assembly, chr names and REF alleles with the file provider. Do not relabel another assembly.
Example verification failedThe search outputs remain available through Full report and Open folder. Keep the full run folder and setup logs. Check RELEASE.json and input hashes before using the example results.
Folder moved / setup incompleteRun Start.command again. It reinstalls the local environment after a move. Existing result folders are preserved.
