# Comparative questions and experimental operations

`comparison_questions.generate_questions(study, records)` turns validated comparison and evidence records into prospective questions, exact requirement slots, assay capabilities, specimen assumptions, operations and named resources. `study` is the resolved result of `comparison_provenance.resolve_study`. The returned output files are `question-records.jsonl`, `question-audit.json` and `question-states.json`. Parent records retain their identities. The audit binds the policy checksum, input snapshot and code identity; a saved stage manifest binds every output byte.

Generation requires one pinned `experiment_policy` JSON input. Its closed schema is `schemas/comparison-experiment-policy.schema.json`. The file declares the common prospective context, experiment and batch, donor universe, scientific rules, specimen assumptions, assay capabilities, costs and finite capacities before question IDs or selected plans exist. Counts have no implicit scientific defaults. Missing donor or technical-repeat counts produce an error naming the missing field.

Each rule declares a source trigger, templates, designs, candidate and intended endpoints, donor and repeat counts, priority, mandatory status, covariate matching and evidence reuse. The supported triggers are candidate nomination, a variant at an intended or nominated candidate locus, differences between retained design nominations, explicitly recorded conflicting observations, missing evidence for the declared endpoint, a sequence-linked prediction, and an existing observation to replicate. Ordinary differences between replicate values do not themselves establish a conflict. Real nomination triggers use the upstream donor/design summary's retained nomination IDs; reconstructed noncarrier counterparts are not silently promoted to nominations. Mock fixtures can list all expected nominations directly.

| Template | Required biological comparison |
| --- | --- |
| `candidate_validation` | One design at the candidate and every intended locus in eligible donors |
| `paired_design_comparison` | Both designs within each canonical donor |
| `variant_association` | One design in independently established carrier and noncarrier arms |
| `design_by_variant` | Both designs within each donor in both genotype arms |
| `evidence_replication` | New measurements excluding the motivating measurement and original experiment, with the declared new experiment, batch, specimen or donor dimension |

A genotype contrast compares outcomes between the declared groups to assess an association. Each arm has its own required independent-donor count. Independence groups must be distinct across the whole question; two specimens, two chromosome copies or technical repeats cannot increase the donor count. A strict policy leaves unknown relationships unresolved. An explicit simulation policy can assign a separately labeled assumed independence group, which is recorded in the eligibility audit. Declared matching covariates must be known and have matching block distributions across arms.

An endpoint/locus pair is exact. For a panel containing the intended endpoint at T and the candidate endpoint at L, the declaration contains those two pairs; it does not imply the candidate endpoint at T or the intended endpoint at L. Every declared question pair applies to every question design. A candidate readout remains required when its locus is another design's intended site. Only an explicitly required intended endpoint at the design's own intended locus has the `intended_activity` role; the other declared pairs remain measurements. For each design, requirements include every intended locus from its design definition. Distinct HBG copies remain distinct loci. An intended readout comes from the independent intended assessment and actual donor DNA, even if that DNA lost its PAM or was never nominated by search. Known altered intended DNA can be assayed. Missing, filtered, unresolved or conflicting required copies block that donor option.

Carrier status is recomputed from both actual chromosome-copy paths and the question's literal allele, haplotype or configuration predicate. Noncarriers use their own reconstructed sequences. Absence of a nomination does not establish reference DNA or noncarriage. Stage 04 already exports donor counterparts at nominated loci, including supported or modeled noncarriers; this layer consumes those records without constructing another genomic search model. Confirmed haplotype predicates require established phase; unphased or unresolved joined haplotypes do not qualify. Retained-callset simulations can use explicitly modeled sequences and receive no empirical donor credit.

`prepare_question_set(study, records)` validates the complete catalog, rechecks pinned input bytes and rebuilds eligibility. It returns a `QuestionSet` with `records`, `index`, and dictionaries for `questions`, `slots`, `actions` and `resources`, plus recomputed eligibility and slot options. `eligible_donor_bundles(question_set, question_id)` returns canonical donor/arm alternatives with independence groups, reasons and exact compatible action/observation choices. Declared allowed IDs restrict the offered catalog; they never override source eligibility. `dependency_closure` rejects undeclared or cyclic prerequisites.

`evaluate_requirements(question_set, selected_action_ids, observation_assignments=None)` checks a dependency-closed selection and returns a feasible joint assignment, completed questions, donor proofs, unfilled slots and separate planning/evidence states. It reconstructs the required A/B, intended, mock and assay-QC structure rather than trusting a supplied slot count. Two technical-repeat slots require distinct actual measurements. Duplicate exports collapse through explicit equivalence or matching source study, experiment, replicate and measured biological identity. A passed QC annotation can accompany its own measured endpoint, but cannot create another repeat or a mock measurement. Sharing one equivalent requirement across questions needs both questions' explicit sharing permission. Ambiguous assignments are checked exactly under the declared `max_expansions`; a limit raises `ResourceLimit`, never a false completeness or infeasibility result. Hard-required questions take precedence over optional weights during joint assignment.

Completed empirical observations must match the donor, design, exact endpoint/locus, context and actual sequence, and pass the recorded control and QC rules. Completed controls additionally identify the actual executed operation, experiment and declared assay/QC capability. A motivating observation, an equivalent export, or its original experiment cannot satisfy replication. Unknown independence on a requested new dimension remains unresolved. Planned controls satisfy future dependencies only. They do not turn a failed or missing observation into passed evidence. A fully planned question with no returned measurements remains `no_measurements`; a complete observed proof is `already_satisfied` and `evaluable`.

Prospective measuring operations declare all locus sequences, exact endpoint coverage, performed control roles and QC operations. Matched controls have the same donor, specimen, context, batch, experiment and repeat, and the declared assay capability. Treatment labels cannot stand in for assay QC. Every measuring operation must include explicit setup, donor, specimen, assay/control and sequencing packages; treated measurements also require matching treatment, and later repeats require their declared repeat package. A panel may include several required operations at one declared price. Zero-cost components remain explicit.

The policy expands finite sequencing pools into named instances before planning. A fixed demand names one `resource_id`. An alternative demand names `eligible_resource_ids`, an `assignment_key`, dimension and quantity. All dimensions with the same action/key use one selected instance, and its alternatives must have the same resource type. The planner records the actual choice and pays each active instance. Per-action repeated dimensions add together. Compatibility, capacity and activation rules prevent sharing a same-priced but incompatible control or creating unpaid capacity. Unbounded resources require an explicit justification and are intended for nonconsumable activation packages.

Simulation specimens require an explicit assumption, capacity and `use_authorized` flag. Research specimen planning requires callable-supported sequence, strict relatedness, a verified physical specimen, permitted and explicitly authorized use, and verified assay feasibility. Public genome records cannot manufacture physical specimens. Existing specimen records without the optional authorization field remain valid archival contracts, but do not authorize a new operation. Inline specimen catalogs are supported. A pinned `question_inventory` input can supply canonical specimen/capability records to both questions and planning. The old `specimen_inventory` role remains planning-only; rename it to `question_inventory` when generation must consume it. Its stage declaration must change to `['questions', 'planning']`.

The declared `max_action_questions` and `max_donor_alternatives_per_arm` control construction scale, using canonical IDs and source eligibility rather than outcomes, costs or priorities. Every suggested scientific question remains present. Questions beyond the construction limit carry `construction_status='excluded_by_declared_limit'`, no materialized slots and an explicit construction gap. They do not trigger a donor-by-endpoint Cartesian expansion. For constructed questions, every excluded donor is audited separately; only the declared eligible alternatives receive slots. A constructed question with no eligible donor is distinct from a construction exclusion. These limits apply to the planning catalog. Evaluator bounds and the declared planning cost unit participate in the question-stage identity, while a budget change alone can reuse questions.

Export the mock fixture with:

```sh
python examples/comparison/questions/build_fixture.py --output /tmp/bes-section9
```

The callable `build_fixture(directory, alternate_carrier=False)` returns `{study, records, labels}`. The export includes pinned inputs, full canonical records and readable label/expected-value mappings for an independent planner oracle. C is a carrier, N is a resolved noncarrier, and optional C2 supplies an independent alternate carrier. A and B share intended test locus T; L is a separate candidate locus. Four treated panels each measure T and L with their required assay controls/QC. Two donor mock packages each measure T and L with their own QC and are explicitly shared between designs.

| Package | Complete fixture cost |
| --- | ---: |
| Study setup | 2 |
| Two donor activations | 2 |
| Four treatments | 4 |
| Four treated T/L panels | 8 |
| Two shared donor mock T/L packages | 2 |
| Declared specimen, sequencing and first-repeat components | 0 |
| Total | 18 |

Costs are in mock simulation units. Disabling mock sharing requires four priced mocks and raises the total to 20. The independent planner package checks the 18-unit completion and the 17-unit shortfall against these same reusable records.

Plan records use the closed `comparison_experiment_plan` family. The compact record binds selected actions, actual resource assignments, totals, question states, source/implementation hashes and the full audit hash. The separate audit retains solver traces, scope and certificates. The audit hash excludes only the embedded plan record, plan ID and the three declared runtime measurement fields to avoid a circular identity. Historical plan revisions remain separate immutable records.
